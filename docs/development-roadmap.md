# Temporal Lab 开发路线

开发重点是让初学者能够解释一条订单如何运行、用真实证据判断恢复与失败，并在理解之后独立实现一个小流程。统一初学顺序见[五阶段学习路径](learning-path.md)：①正常订单与角色分工 ②等待确认时停止重启 Worker ③重试、超时与幂等 ④取消、补偿与心跳 ⑤Signal / Update 深入对照。

当前状态：**三期及开发收尾均已完成并验证（2026-10-27）。** 第一期建立统一学习路径，第二期接通真实源码、当前 Run 证据与事件引用，第三期补齐开放自测、手工实验记录与可独立运行的迁移练习。以下记录实际交付与验收；参考实现测试通过不代替学习者自己的作答、实现和证据解释。

## 范围与约束

- 以现有订单和真实 Temporal 数据为教学基础，不扩张高级功能；不改变现有订单协议、接口语义或业务行为。
- 保留现有 Worker 恢复向导及其证据判定，不另造停机流程。独立进程控制使用 `npm run worker:recovery`，操作条件以[恢复向导](worker-recovery-guide.md)为准。
- 不增加学习进度后端，不自动打分。学习效果通过预测、实际观察、解释和独立实践体现。
- 区分可照走的现有实验、正在整理的学习入口和后续练习；不把计划写成已上线能力。

## 第一期：学习入口与核心模型（已完成）

**目标**：让初学者先走通正常订单，理解 API、Server、Worker、Workflow、Activity 的分工；随后通过等待确认时的 Worker 恢复，理解事件历史和确定性重放。

**具体交付**：

- 统一 README、文档目录、页面学习入口的五阶段顺序。正常订单默认使用 Signal，第一课聚焦 Query、History 和角色分工；Update validator、ID 去重等深入内容放到第五阶段。
- README 五分钟体验改为“正常处理 → 等待确认 → Signal → 完成 → 回看 History”，随后指向 Worker 恢复课，保留高级对照文档链接。
- 提供 [learning-path.md](learning-path.md)，每阶段包含目标、操作入口、观察证据、文档与源码；让学习者先写预测，再用事件解释结果。
- 将 History 与重放前置：说明 Server 保存历史、Worker 重放重建变量、已记录 Activity 成功结果被复用；说明 Workflow 缓存存在，以及结果未记录时 Activity 仍可能重跑。
- 推荐源码阅读顺序统一为 API 启动调用 → Worker 注册 → Workflow 主干 → Activity 实现；前端轮询、旧 Query 与证据保护放到后续阅读。
- 页面保留精简学习入口，顶部与入口的开关同步；五阶段说明按需展开，基础代码摘录先展示编排主干，进阶消息与心跳摘录另行展开。
- 同步根 README、文档目录、执行流程、本路线和学习路径；将最近实验的“Replay a run”改为“View past runs”，handler 注册注释改为建议尽早注册。

**依赖**：现有正常订单、默认 Signal、Query / Describe / History 观察视图；已有“等待确认时重启”向导、独立 `worker:recovery` 方式和支付账本。不依赖第二期源码拆分，也不需要先完成第三期练习。

**可验证验收**：

- [x] README、文档目录、执行流程与页面学习入口使用相同的五阶段顺序，首课场景为正常处理、确认方式为默认 Signal。
- [x] 按第一课说明在真实浏览器中创建并完成正常订单，观察 Signal 收件回执、业务 `completed` 与执行 `COMPLETED`，未使用 Update 校验或去重。
- [x] 同一个 Run 的真实 History 含库存和付款完成、`TimerStarted`、`WorkflowExecutionSignaled`、`TimerCanceled`、发货完成和 `WorkflowExecutionCompleted`；账本为尝试 1 次、扣款 1 次、退款 0 次。需要事件 ID 或 Payload 时，文档指向官方 Temporal UI。
- [x] 第二课复用已有恢复向导，核对说明顺序为先取得 Query 中断与 History 边界，再在停机窗口发送 Signal、认证入库后重启。本期只核对入口与说明，未重复执行停机实验。
- [x] 页面和文档前置 Server History、Worker 内存与重放的关系，明确成功结果复用、未确认完成可能重跑及 Workflow 缓存；实际学习掌握程度留待第三期自测与练习检验。
- [x] 入口改动沿用现有协议、场景与业务处理，没有新增学习进度后端、自动打分或伪造观察数据。

**验证记录**：`npm test` 72 项通过；新增两项前端交互回归，覆盖双入口状态同步、展开阶段保持、导航目标、查看路线不创建订单，以及代码标签的键盘操作和进阶摘录展开。`npm run build` 通过。真实浏览器检查桌面与 375px 窄屏、键盘焦点、原生展开控件和减少动态效果设置；页面无横向溢出。

## 第二期：源码分层与运行证据对照（已完成）

**目标**：让学习者可以先读核心编排，再按需深入实验机制与观察保护，并能把源码中的关键决策和真实运行证据对应起来。

**具体交付**：

- 新增「深入观察 → 源码与证据」，按 API 入口、Worker 注册、Workflow 核心主干、Activity 实现提供真实摘录和按需展开的阅读边界。保留单一 `orderWorkflow` runtime，用符号与摘录分层，不复制教学 Workflow。
- 九个主题串起“问题 / 操作 → 编排决策 / Activity → 当前运行证据 → 机制与解释边界”，覆盖正常、恢复、重试、超时、幂等、取消与补偿、心跳、Signal、Update。配套 [source-evidence-guide.md](source-evidence-guide.md)，并接入五阶段学习路径。
- 摘录从六个固定源码文件按定位表达式提取，自动计算当前行号，并在首次打开标签时加载；回归测试核对全部摘录的正文与行号。没有新增任意本机文件读取接口；「核心代码概念」继续保留教学示意。
- 证据分别注明 History、Query、Describe、SQLite 或真实 HTTP 回执来源，明确已读到、待观察与过期。Query 单独失败和整个响应失败分别标记，不以旧 Query 补齐新尝试心跳，也不用 History 数量代替扣款次数。
- History 显示真实 `#ID`；证据引用可跳转并聚焦对应事件，返回时保留主题，切换 Run 后重置上下文。事件直接展示转换后的 detail，Update 对照保留原请求标识、真实拒绝消息和 handler 返回值，不从 Completed 名称推断成功。
- 恢复主题解释当前快照；跨请求的基线、停机窗口、Signal 入库与恢复判断仍由原向导负责。

**依赖**：第一期学习顺序与核心模型稳定；现有 API 契约、恢复证据规则和业务行为作为兼容基线。涉及源码整理时，依靠项目已有验证覆盖正常订单、重试、超时、取消、补偿、心跳与确认方式。

**可验证验收**：

- [x] 提供 API → Worker → Workflow → Activity 的真实摘录、符号和行号，编排主干可连续阅读，实验与观察辅助逻辑可按主题定位；新读者实际掌握程度留待第三期检验。
- [x] 对五阶段中的关键操作，均可从导读定位到源码符号与真实证据；文档不会用 History 事件数代替扣款次数，也不会把心跳当作逐批 History 事件。
- [x] 运行对照覆盖正常、恢复、重试、超时、幂等、取消、补偿、心跳和 Signal / Update；无法取得的证据显示未知或待观察，示例不冒充实际运行结果。
- [x] 现有订单协议与业务行为保持一致，完整回归通过；Worker 恢复仍按原向导核对同一个 Workflow ID / Run ID，本期未重复操作用户环境的 Worker 停机。

**验证记录（2026-10-27）**：`npm test` 83 项通过（较第一期新增 11 项）；最终细节调整后，证据模型与前端交互 17 项再次通过，`npm run build`（含类型检查）通过。新增覆盖真实摘录定位、未知数据、Query 与整次响应的过期状态、旧 attempt 心跳、Update 失败 outcome / 返回值、同 Run 的事件跳转及切换 Run 的上下文重置。真实浏览器核对九主题的源码加载、桌面与 375px 窄屏、键盘展开及焦点，页面无横向溢出，浏览器无脚本错误；校验拒绝实验的 HTTP 409 为预期业务响应。

## 第三期：自测与小型迁移练习（已完成）

**目标**：验证学习者是否能够在没有逐行答案的情况下预测结果、用证据解释原因，并把相同机制迁移到一个小流程。

**具体交付**：

- 新增页面「自测与迁移练习」与 [self-check.md](self-check.md)。10 个开放题覆盖五阶段的角色、重放、重试、结果未知、Timer、取消补偿、心跳、Signal / Update 与观察边界，每题提供操作、所需证据和默认折叠的参考要点；学习者先写预测，再自行核对。
- 新增 [experiment-record-template.md](experiment-record-template.md)，按预测、环境、实际操作、来源、同 Run 引用、机制解释和结论边界组织记录。页面可手工输入作答与实验笔记并导出 Markdown；草稿只在本次页面中保留，刷新 / 关闭会清空，失败时提示复制保存。
- 提供 [资料审核迁移题目](../exercises/01-transfer/01.01-document-review/problem/readme.md)，在 `problem/workflow.ts` 先独立完成准备资料 → Signal / 超时等待 → 归档或清理，再按题目入口查阅参考实现；初始 TODO 明确失败，不伪造成功。
- 练习使用专用 Task Queue 与独立 SQLite 模拟资料账本，提供启动、观察、Signal 确认、取消和结果查询 CLI。正常完成、等待时恢复、准备已提交但响应丢失后的幂等，以及取消 / 超时清理均要求引用真实事件和账本；题目与参考 Worker 不同时消费同一队列。
- 页面入口、README、学习路径与文档目录相互关联；保留订单协议和现有恢复向导，没有新增自动评分或学习进度后端。

**依赖**：前两期提供稳定的五阶段路径、清晰的源码定位与真实证据对照；学习者已完成对应基础实验。迁移练习只使用本地模拟操作，不依赖真实支付或外部业务接入。

**可验证验收**：

- [x] 自测题有清楚的作答入口、核对要点与证据要求，学习者能自行记录和解释；没有学习进度后端或自动评分。
